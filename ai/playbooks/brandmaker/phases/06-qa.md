# Phase 06 — QA & handoff

1. **Parity audit.** Open `brandmaker/PARITY.md` and walk it item by item against the real
   directory tree. Fix gaps before reporting; do not present a checklist of excuses.
2. **Link & path audit — mechanical.** Script it: every `href`/`src` in `site/`, every
   `url()` in every CSS file, and every file named in `SKILL.md`'s Layout resolves on disk.
   Counts in prose match reality. A skill whose docs cite a file it doesn't ship is broken
   regardless of how good the docs are.
   **This audit has one blind spot, and it will lie to you.** A `url()` inside a CSS custom
   property resolves against the stylesheet that *consumes* the `var()`, not the file that
   declares it — so a path written inline on an element and read by `docs.css` is checked
   against the wrong directory and passes. A real run shipped 40 blank icons with the audit
   reporting 912/912 resolved. Set `url()` directly on the element or in the stylesheet that
   owns it, never handed across files through a variable, and treat item 11 as the only check
   that can see this class of failure.
3. **Reference & anchor audit — mechanical.** Every reference MD's `Rendered:` path resolves
   to a shipped page, every `#<section-id>` it cites exists in that page's HTML, and every
   major site-page section carries a stable `id`. Line ranges are gone; the path and the
   anchor are what remains, so they are the part that must actually resolve.
4. **Consistency audit — including the generator.** `SKILL.md`, `tokens.css`, the reference
   MDs **and any content model that emits them** state the same values everywhere: one usage
   ratio, one radius table, one type scale. Script the hex comparison across all of them.
   A generator holding superseded values is invisible in the shipped output and reverts the
   docs the moment someone rebuilds — assert it, don't read it.
5. **Superseded-value audit.** Every hex the palette moved away from during the run is gone
   from every file, generator included. Keep the list; it is the cheapest check that catches
   a half-applied palette change.
6. **Accessibility audit.** Compute contrast for every documented fg/bg pair; every failure is
   fixed or carries a written exception. `SKILL.md` states the policy and the tightest
   surviving pair — not the table. Confirm touch-target minimum, focus-visible spec, and
   `prefers-reduced-motion` handling are documented and reflected in the CSS.
7. **Stance audit.** Dark mode, motion, and responsive each have a stated position in
   `SKILL.md` — "not supported, because…" passes; silence fails.
8. **Scope audit.** Grep for audience nouns ("teams", "users who", "designed for"),
   positioning verbs ("helps you", "lets you", "makes it easy"), and taglines. Then apply the
   removal test to each hit: cut the sentence and ask whether a rule became unusable — if yes
   it stays, if it only said what the product does it goes. Do **not** grep for the brand name
   as a sentence subject; design statements use that shape constantly and the check returns
   nothing but noise. Also confirm there is no `README.md` and no `CHANGELOG.md`.
9. **Voice & locale audit — mechanical first, then read.** Grep before you skim: for an en-US
   build, `colour|centre|apologise|licence|behaviour|organise|labelled|grey` and the rest of
   the British set; invert it for en-GB; the equivalent register and diacritic checks for
   other locales. A real run *skimmed* this item and shipped 148 British spellings in a system
   whose frontmatter declared `en-US` — the largest defect in that run, and invisible to every
   other check. Then read for the things a grep can't see: CTA casing, lorem ipsum, and
   leftover text from any other brand.
10. **Placeholder & licensing disclosure.** If fonts or logos are generated placeholders,
    `SKILL.md`'s Marks section and the typography reference say so and explain how to swap
    real assets in. Every font and icon license from the ledger appears in `SKILL.md`.
11. **Render audit.** Open `site/index.html` and at least three pages in a real browser, in
    **every theme the brand ships** — both, unless the dark-mode stance is "never" — and look
    at them. A hard-coded color only shows up in the theme nobody opened, and a screenshot is
    the only thing that proves a page renders at all. Then open the widest page again **at a
    phone width** and check every collapse behavior phase 03 specified. This is the only check
    that sees them: a table with `overflow: hidden` reports no page overflow and is silently
    missing its last two columns.
12. **Delete working artifacts.** `<brand>-skill/.ledger.md`, every checkpoint and scratch
    page, anything produced to make a decision rather than to record one. What ships is what
    someone will open, trust, and have to keep true.

## Handoff message

Tell the user, in this order: where the skill lives (`./<brand>-skill/`), how to browse it
(open `site/index.html`), how to use it in a project (copy `tokens.css`, `<brand>.css`,
`fonts/`, `assets/`; link tokens first), that `SKILL.md` is the one document to read, what's
placeholder and how to swap it, **every `AI-default-final` decision from the ledger** (the
load-bearing calls nobody signed off on), and any parity items intentionally scaled (with the
user's earlier approval cited).
