# The standing concerns

Every upgrade checks every item, whether or not the changelog mentions it. Each is a kind of change that has hurt, or nearly hurt, a past bump. The reader looks for the change, the mapper for Sova's exposure, the tester for the effect. A concern with no finding is still listed in the judge's report, as checked.

**The canaries don't see everything.** A canary can keep passing while its row's prose has gone false, and `quirks-meta.test.ts` scans only `server/` and `shared/`. Read the row, not just its result.

1. **Hooks firing on new kinds of turns.** pi may start firing a hook on a turn it used to skip (`before_agent_start` began firing on runs an extension's message starts), so a handler that assumes "only a user prompt reaches here" now runs on others. List every handler (`rg 'before_agent_start|"agent_start"|"input"' server pi-config`) and hunt the comments and QUIRKS prose that state the old assumption. Usual places: `server/harness/pi/modes.ts`, `server/harness/pi/playbook.ts`, `server/served-tools.ts`, `server/overseer.ts`, `pi-config/extensions/mode/index.ts`.
2. **Busy and idle at turn start.** When `isIdle()` and `isStreaming` flip relative to the hooks and `agent_start`, and what `sendUserMessage` and `sendMessage` require in that window (`deliverAs`). Anything that reads "streaming" as "the run has started": `server/baton-*`, `pi-config/extensions/claude-code/provider/auto-compact.ts` and its `DESIGN-bridge.md`, the settle window (P5).
3. **Tool activation and order on resume.** Which tools a resumed chat has, what `setActiveTools` does to the order, what `defaultActive` means. The order is part of the request prefix, so it decides the prompt cache. Sova promises a reopen keeps the fresh chat's order (§app.project-services/tool-offered). Usual places: `server/served-tools.ts`, `server/harness/pi/memory.ts`, `server/harness/pi/mcp.ts`, P22, P23.
4. **Tool arguments and schema libraries.** Who validates, with which library, what is still re-exported (`Type`, `Static`, `StringEnum`), and whether the extension loader's view of a package differs from its real entry (under Bun a file outside pi's loader gets the real entry). Also the validation text the model reads, and tests that match it. `rg "from 'typebox'|from \"typebox\"|StringEnum" pi-config server`; `pi-config/extensions/claude-code/provider/mcp-host.ts`.
5. **Compaction.** What triggers it and what budgets its summary, what gets serialized, the hooks around it, its error text (P3) and its write path (P2). `server/harness/pi/history-ops.ts`, `server/harness/pi/memory.ts`, `pi-config/extensions/compact-handoff/`, `pi-config/extensions/claude-code/provider/auto-compact.ts`.
6. **System prompt and tool guidelines.** Reworded base text churns the goldens and loadouts, changes what every chat's model reads, and resets a prompt cache once. Report what the new wording drops or adds, in a sentence, not just that it changed. `server/agent-loadouts.snapshot.json`, `server/harness/pi/golden/special-model-view.json`, the modes goldens.
7. **Session files, and old and new chats sharing them.** `CURRENT_SESSION_VERSION`, entry types, roles, fields, the order keys are written in. Sova's reader (`KNOWN_TYPES`, `KNOWN_ROLES` and the line scanners in `server/harness/pi/reader.ts`), the second parser in `pi-config/extensions/subagents/adapters/pi.ts`. After landing, chats on the old code and chats on the new run side by side until each reloads, so each must read what the other writes. A new session version is a one-way door: `SessionManager.open()` rewrites a file when it migrates it, and old pi can't read the result. If `<new>` bumps it, that goes at the top of the report.
8. **Deep imports and copied pi code.** No canary covers these. Check each against `<new>`:
   - `scripts/mesh-vps/warm-extensions.mjs`: a copy of pi's extension alias map (`getAliases`).
   - `scripts/hermetic-agent-dir.mjs`: re-implements pi's extension entry rule.
   - `server/harness/pi/system-replay.ts`: imports pi-ai's `dist/utils/transcript.js` by file URL.
   - `pi-config/extensions/llm-inflight/runtime.ts`: replaces `ModelRuntime.stream` and `streamSimple`.
   - `pi-config/extensions/subagents/fork/cache.ts`: reassigns `agent.streamFunction`, and names provider options.
   - `pi-config/extensions/provider-limits/index.ts`: casts the model registry and wraps `streamSimple`.
   - `pi-config/extensions/{model-levels,usage-status,stamp}/index.ts`, `subagents/fork/child.ts`: casts over pi objects.
   - `pi-config/extensions/topic-outline/anchors.ts`: mirrors pi's `parseSkillBlock`.
   - `server/sync/logins-stores.ts`: writes `auth.json` itself under pi's `proper-lockfile` lock; copies a pi constant (`PI_REFRESH_WINDOW_MS`) and an error text.
   - `server/harness/pi/package.ts` (`requireFromPi`): breaks if pi drops the dependency.
   - `shared/image-note.ts`: pi's image-resize note format.
   - `server/harness/pi/open.ts`: relies on an unknown `--flag` being a diagnostic, not fatal.
   - `server/sync/*.test.ts`: deep-import pi's `dist/core/auth-storage.js`.
9. **Private members.** Diff the private members in `dist/core/agent-session.d.ts` and compare them with what Sova reaches, in tests too (`rg '\._[a-zA-Z]+' server pi-config -g '*.ts'`).
10. **Terminal drawing stand-ins and HTML export.** A chat process replaces pi's terminal drawing code (P27). A new file in those folders needs classifying in `server/harness/pi/headless-files.json`, and code outside the terminal mode must not start importing a drawing module (HTML export is where that has happened).
11. **pi-config is not typechecked.** `tsconfig.json` includes only `server`, `src` and `shared`, so a broken extension still builds. Read the type diffs against `pi-config/` by hand. Its suites are the `## Tests` block of `pi-config/README.md`, and `pi-config/extensions/claude-code/provider/typecheck.mjs` typechecks that one provider. Both default to the global pi, so point them at the pi under test with `PI_PACKAGE_DIR`, or they test `<terminal>` and pass for the wrong reason.
12. **Extension loading, and what pi validates at start.** The loader's aliases, native loading under Bun (P26), a package pi drops or adds, the path rewrite (P24). Also anything pi parses or validates at start from what we ship (`themes/`, `pi-config/settings.json`, `pi-config/keybindings.json`, `pi-config/models.json`), for the chats and the terminal pi both: a tightened schema can stop a start.
13. **Providers, models, auth.** Default models, models pi removed that `pi-config/models.json` or model levels name, new base-URL requirements, the shape of `auth.json` and its lock, the login prompts Sova answers (P37, P38), provider option names.
14. **Mesh peers on another pi.** A peer runs what its deployed commit's lockfile pins, so it lags. Wire 1 is pi's own events nearly raw (`server/harness/pi/wire.ts`, `shared/wire-v1.ts`); no `wire-areas` number tracks them, and the hello's `pi` field decides nothing. Login sync copies `auth.json` entries between hosts. Ask: does a browser on the new code still draw a live chat from a peer on `<old>`, and the reverse?
15. **Tests whose premise is pi's speed or tick order.** When pi gets faster or reorders a tick, a test can fail while the product improves (`server/stream-guard-runtime.integration.test.ts`). Run each such failure alone and under load, at both versions. Decide whether the premise still holds, and whether the thing the test guards is still needed.
16. **The way a bump reaches a copy.** `server/updates/runner.ts` has no pi logic: a bump arrives as a lockfile change, and peers install with `--frozen-lockfile`. Check `allowBuilds` for new install scripts, and `engines` against `mise.toml`'s Node and Bun.
17. **Golden churn is evidence, not noise.** A bump moves the recordings: new persisted or event fields, reworded text, and ordering shifts. An ordering shift is behaviour until someone explains it. Re-record at both versions, and tie every diff at `<new>` to the one release that caused it; a diff with no cause stays open. Wire-1 frames are a compatibility contract and are never re-recorded ("change the server, not the file"), so a wire-1 difference is a finding for concern 14.
18. **Workarounds that can go.** For every QUIRKS row, is its "Retire when" now true? For `docs/bun-quirks.md` too. An upgrade's value is often what Sova can delete.

Each run that finds a new kind of change that hurt, or nearly hurt, adds it here: the list grows with every upgrade.
