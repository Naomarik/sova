## Contract questions / deviations

1. **Asked and resolved as contract v1.1:** `.table` and `.badge` are not in base.css, and nothing
   was ported. The pinned list is `.button .card .cluster .text-num .icon .chip .chip-dot
   .chip-success|warn|error|info`. The WS target keeps the api path prefix (http→ws, https→wss).
2. **Beyond the contract, not in conflict with it:**
   - A plain GET on `/ext/<id>/ws/*` is 426.
   - `/ext/<id>` redirects to `/ext/<id>/`.
   - A missing `title` falls back to the id; `icon` must match `[a-z0-9-]+`.
   - A duplicate id is dropped.
   - `api` must have an explicit port and no credentials, query or fragment.
3. **The page has a head above the iframe** (back, title, status chip, Reload, Open in New Tab),
   like Usage and Agents. The contract says "full-pane iframe". The head is needed for the back
   link at folded width and shows the down reason. Say if you want it gone.
4. **Timeouts.** The 10 s connect timeout is Node fetch's default; I set no read timeout. Node's
   fetch (undici) still cuts a response body that goes **300 s with no chunk**, and changing that
   needs an undici Agent, i.e. a new dependency. Job streams should send a heartbeat more often
   than every 5 min. This is written into `§app.extensions/serving`.
5. **Vite on this host.** Without `--host 127.0.0.1` it binds `[::1]` only, so
   `http://127.0.0.1:5186` fails. PLAN §5.1's command should add `--host 127.0.0.1`.
6. **Untracked helper:** `.claude/skills/playwright/scripts/node_modules` is a symlink to the main
   checkout's skill install, which the worktree lacks. It is untracked and not committed. `node_modules/` in .gitignore does not match a symlink, so it shows as `??`; never add it.

## v1.11 Phase 2 (pending "GO host"): corrections to the PLAN-v1.11 §4.5 file table, approved by the coordinator

1. **Stacking.** `var(--z-overlay)` doesn't exist in `tokens.css`. The maximized iframe uses
   `z-index: 40`. That is above the resizer (5) and the subagents pane (10), and below the
   scrim/modal (50/51), toast (60) and skip-link (100), so Sova's own dialogs and toasts still
   show over a maximized extension.
2. **What is hidden.** Sova's sidebar class is `.app-sidebar`, not `.sidebar`. The maximized rule
   hides `.app-sidebar` and the extension page's own `.session-head`, scoped to the extension view.
3. **When it restores.** "Restore on any route change" means on `hashchange`. The host's own
   `sova:route` mirroring uses `history.replaceState`, which fires no `hashchange`, so mirroring a
   sub-route never restores.
