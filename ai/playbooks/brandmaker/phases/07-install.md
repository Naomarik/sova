# Phase 07 — Install into a Rakiba project (optional)

Inputs: a QA-passed `<brand>-skill/` (phase 06 signed off) and a target Rakiba project
directory. Run this phase only when the user wants the skill wired into a project; a
standalone skill handoff ends at phase 06.

Ask (or confirm from context) the target project path. A valid target has `rakiba.edn` at
its root and a `resources/sass/style.scss`.

## What "installed" means

Two things, both idempotent (re-running after a rebrand overwrites the generated pieces
and touches nothing human-owned):

### 1. The skill, discoverable by agents

Copy the entire `<brand>-skill/` to `<project>/.claude/skills/<brand>-design-skill/`. The
destination directory matches the generated skill's frontmatter `name`. Claude Code
auto-discovers skills there, so any future styling work in that project loads `SKILL.md`,
the token reference, and the component docs on demand. Do not prune the `site/` directory —
it is the visual reference.

### 2. The CSS, wired into the existing SASS pipeline

Rakiba projects compile `resources/sass/style.scss` → `resources/public/static/css/style.css`
via `bb sass` (see `rakiba-sass-build!` in rakiba-lib). Plain CSS is valid SCSS, so the
skill's CSS drops in without any plumbing changes:

1. Copy `tokens.css` → `<project>/resources/sass/brand/_tokens.scss`
2. Copy `<brand>.css` → `<project>/resources/sass/brand/_components.scss`
3. Prepend to both copies:
   ```scss
   // GENERATED by brandmaker from .claude/skills/<brand>-design-skill/ — DO NOT EDIT.
   // To change the brand: edit the skill (or re-run brandmaker), then re-install.
   ```
4. Ensure `style.scss` starts with (add if missing, never duplicate):
   ```scss
   @use 'brand/tokens';
   @use 'brand/components';
   ```
   `style.scss` remains human-owned — only add these two lines; never reorder or remove
   anything else in it.

Hand-written partials layer on top by consuming the custom properties
(`var(--clr-…)`, `var(--space-…)`) — never by redefining them.

### Assets

- Fonts: copy `fonts/` → `<project>/resources/public/static/fonts/<brand>/` and rewrite the
  `@font-face` `url()` paths in `_tokens.scss` to `/static/fonts/<brand>/…`. The skill copy
  under `.claude/skills/` keeps its relative paths (it must stay self-contained).
- Logos/icons: copy `assets/` → `<project>/resources/public/static/img/brand/`. Tell the
  user the paths so they can reference them from views.

## Source of truth

The skill directory (`.claude/skills/<brand>-design-skill/`) is canonical. The files under
`resources/sass/brand/` and `static/fonts|img/` are generated copies. A rebrand is:
edit the skill (or re-run brandmaker phases as needed) → re-run this phase.

## Verification before declaring done

1. `bb sass:build` (or one compile cycle of the running `bb sass` watcher) succeeds with
   the brand partials included.
2. Open the app (or a rendered page) and confirm base elements pick up the brand: body
   font, link color, heading scale. A page that still shows browser defaults means the
   `@use` lines didn't land or load order is wrong (tokens must load first).
3. Check the network/console for 404s on font files — the most common install failure is
   an unrewritten `@font-face` path.
4. Report to the user: what was copied where, the two lines added to `style.scss`, and the
   rebrand procedure.
