# pi 0.87.1 → 1.0.3: Sova's performance before and after (2026-10-06)

**Result:** the pi 1.0.3 bump made no user-visible performance difference to Sova. Cold start, memory, turn latency at every session length, steer and follow-up, and compaction are all within noise. Five metrics moved beyond their noise floor, all by milliseconds:

- slower: `GET /api/models` warm (+1.4 ms), `set_model` (+1.2 ms), opening the 500-entry session (+5 ms), and `pi --mode rpc` with extensions discovered (+22 ms, +7%).
- faster: opening the small real session, the first open in a new cwd (−45 ms).

pi 0.99.2's claim that "prompt submission no longer slows with session length" doesn't show up in Sova's path. On both versions, the time from prompt to model request grows the same way with session length: about 11 → 16 → 32 → 61 ms at 50 → 500 → 2000 → 5000 entries. The `send_ack` stayed at 2–6 ms on both.

Base = master `16ca9baf` (pi 0.87.1). After = `feat/pi-1.0` `2b19b824` (pi 1.0.3). Both were clean `git archive` snapshots with their own `pnpm install --frozen-lockfile`. There were 10 interleaved A/B rounds plus a 6-round A/A (base against itself) for per-metric noise floors. Raw samples are in `docs/perf/data/pi-1.0/{ab,aa}/`.

Not beyond noise but worth watching, because they lean the same way: the first runtime open (+23 ms, 7/10), the warm open (+3.4 ms, 8/10), and the first `/api/models` (+1.6 ms, 8/10). Together with the synth-500 open, they suggest pi 1.0's session open costs a few ms more per runtime. The real-medium and real-large opens didn't move, so this cost doesn't grow with the file. Its cause was not investigated. The 0.87.1 → 1.0.3 difference in a CLI worker without extensions (+20 ms) is only 6/10 rounds.

## Method

`scripts/perf-pi/run.mjs` (README alongside). All builtins. Nothing touches the live server, `~/.pi` (its sessions were read once, by `--prepare`), or systemd.

- **Trees.** Base: `git archive 16ca9baf` into `.agent/perf-base`. After: `git archive 2b19b824` into `.agent/perf-after`. Each has its own `pnpm install --frozen-lockfile`. The runtime code is unchanged between `94157606` and `2b19b824`; only goldens, `CLAUDE.md` and the lockfile changed.
- **Servers.** Each tree's `scripts/start-server.sh` on Bun 1.4.2, the `dev:hermetic` entry. Ports 4870 (base) and 4871 (after), one at a time. `PI_CODING_AGENT_DIR` is a fresh copy, every run, of that side's hermetic agent dir. The agent dir is built by that tree's own `scripts/hermetic-agent-dir.mjs --copied-sessions`, so it has that tree's pi-config extensions and no wake nudge.
- **Hermetic environment.** `HOME` and `CLAUDE_CONFIG_DIR` point under `.agent/perf-pi/<side>/home`. `scripts/fake-claude.mjs` is first on `PATH`. The environment sets `PI_OFFLINE=1`, `PI_SKIP_VERSION_CHECK=1`, `PI_TELEMETRY=0` and `SOVA_PRICES_FETCH=off`.
- **Model.** `scripts/perf-pi/mock-llm.mjs` is a loopback OpenAI-compatible endpoint on port 4879, registered in the agent dir's `models.json` as `perfmock/mock-1` and `mock-2`. It follows the pattern of `scripts/harness-wire-e2e-mock-llm.mjs` and the models.json shape of `scriptedModelsJson`. pi's real openai-completions provider talks to it, so no network and no auth are involved.
  - Replies are 8 text deltas, 15 ms apart; compaction requests get a one-chunk summary.
  - The mock logs each request's arrival. "Prompt → model request arrives" is therefore pi's and Sova's work before the HTTP request goes out.
  - The in-process `ScriptedModel` was not usable: it patches a session object, and the runtime here lives in a separate Bun server.
- **Sessions.**
  - Real sessions were copied in from `~/.pi/agent/sessions`: the 25th-percentile file (35 entries), the 75th-percentile file (320 entries, 1.1 MB), and 01a0f6e0 (3778 entries, 10.9 MB, the largest under 12 MB). Every 12th file was also copied for the listing, 79 files in all. Each header's `cwd` was moved to a scratch dir, so no runtime ran in a real project.
  - Synthesized sessions have 50, 500, 2000 and 5000 entries (`sessions.mjs`, the entry shapes of `golden/fixtures/large.ts`; 5000 entries = 6.8 MB, a 5.6 MB model request). There are also ten 300-entry sessions for the memory phase and a 500-entry compaction subject.
- **One server run.**
  1. Cold start to the first `/api/health` 200 (polled every 10 ms).
  2. RSS (`/proc/<pid>/status` VmRSS) after 10 s idle.
  3. `/api/models` ×10, `/api/sessions` ×10, transcript tail ×10.
  4. Ten runtime opens over `/ws/chat?force=1&tail=rest` (connect → `hello`), 500 ms apart, with RSS at 1, 5 and 10 runtimes. The first of these opens pays the one-time module and extension load.
  5. One open each of the sized sessions.
  6. Five turns at each session length.
  7. Three rounds of prompt, steer at the first text delta, and follow-up.
  8. `set_model` there and back, three times.
  9. One compaction (the mock saw the summarization request every time).
  10. RSS, then the whole-transcript control.
  11. SIGTERM.
- **pi CLI.** `node <pkg>/dist/cli.js --mode rpc --model perfmock/mock-1 [--no-extensions] --session-dir …` to the first `get_state` answer. That is the readiness `pi-config/extensions/subagents/runner.ts` waits for, and the runner passes `--no-extensions` by default. Base is the global pi 0.87.0 (the one workers run). After is 1.0.3 in a scratch npm prefix under `.agent/pi-cli/`. The control compares the global 0.87.0 with a scratch 0.87.0, which isolates the install-layout effect. The "extensions discovered" variant loads that side's hermetic agent dir's extensions.
- **Rounds.** Round 0 is an unrecorded warm-up that fills Bun's transpiler cache, Node's compile cache and jiti's extension cache. Before the warm-up, an extension-loading CLI start took 1.8–2.1 s instead of ~0.3 s. In 10 rounds, the base/after order alternates each round, then a CLI round follows. The A/A batch is 6 rounds with base on both sides (same agent dir template, same CLI). A round took about 100 s.

## Machine state

- 32-core AMD Ryzen AI Max+ 395, 121 GB RAM, Linux 7.0.5, Node 25.2.1, Bun 1.4.2.
- A/B ran 22:01–22:19 UTC and A/A 22:20–22:30 UTC, on 2026-10-05 (02:01–02:30 local, 2026-10-06).
- The harness waited for load1 ≤ 24 before each round: 60 s before round 1 and 30 s before one later round.
- Load during the A/B: load1 11.6–26.8 (median 14.6), cpu PSI "some" avg10 median 0.8%, max 15.7%.
- Load during the A/A: load1 7.4–27.2 (median 10.4), PSI median 0.2%.
- Other sessions' workers were running throughout. The bump worker was idle (per the orchestrator); a codemode worker was editing files without running tests.
- Zero errors in all 32 server runs and 16 CLI rounds.
- `~/.cache/sova-monitor/mon.log` could not be read: this session's `~/.cache` is a private sandbox mount.

## Caveats

- **The A/A shows a side bias on some cheap metrics.** With the same tree on both sides, the "after" side was faster in 6/6 rounds on cold start (−23%), the real-small open (−8%) and the transcript tail (−22%). The sides differ only in port, `HOME`/agent-dir path and the order within a round. The per-metric floors absorb this, but the real-small open's −42% in the A/B is partly this bias: still well beyond the floor, though the real gain is likely smaller. Cold start needs more than its 6% to be called.
- **Absolute scale.** The changes called beyond noise are 1–5 ms on server paths and 22 ms on a worker start. None is visible to a user next to a model's latency.
- **The mock model.** It streams in ~120 ms and the requests stay on loopback. Turn numbers are therefore Sova + pi overhead only, not what a real provider adds; pi-ai's provider code for other APIs (Anthropic, Codex) was not exercised.
- **Not measured:**
  - Claude Code provider turns.
  - Real-provider streaming.
  - The browser.
  - Heap: Bun exposes no V8 heap here, so memory is RSS only.
  - Extension load time on its own: "first runtime open" minus "warm open" (~62 ms base, ~82 ms after) is the closest proxy.
- **Snapshots, not the live tree.** Both trees are archives. The base `pnpm install` used a private store under `.agent/`. The sandbox's read-only `/tmp` breaks pnpm 12's store lock; it ran under `unshare -Urm` with the sandbox's `TMPDIR` bound over `/tmp`. Same lockfile, same packages.
- **The controls' code paths are unchanged.** `/api/sessions` and `/api/transcript` are Sova's own code, and `2b19b824` doesn't change them. Their Δ (+0.15 ms, 0, +3.4 ms) was within their A/A floors.
